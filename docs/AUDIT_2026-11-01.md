The live result was correctly **inconclusive**: gateway replies and transfer speeds cannot establish CPU, memory, campus topology or a full root cause. The application retained missing values instead of inventing measurements.

## Bug found and fixed

A supplied device ID such as `assessment`, `group:0` or `action:0` could collide with an internal dependency graph node. Reproduced with a failing regression test, then fixed by using an internal namespace unavailable to valid device IDs. The full 71-test backend suite passed afterward. Existing immutable reports remain unchanged.

## Limits and items not fully verified

- DOCX structure and embedded graphics passed; Word page layout remains visually unverified because LibreOffice is absent from the bundled runtime.
- Live collection measures the local default gateway and Internet transfers. Full campus auto-discovery, SNMP collection and live device CPU/memory collection are not implemented.
- External email/push delivery, public sharing, multi-user authentication and automatic remediation are not implemented.
- Anomaly detection needs at least five comparable historical readings. It flags changes; it is not a trained outage prediction model. Agent confidence is a documented heuristic, not a calibrated probability.
- Monitoring requires the server and computer to stay running. Sleep/downtime is not recorded as healthy coverage.
- Non-blocking build chunk-size and test-client deprecation warnings remain.

Machine-readable live audit: `output/verification/live-audit.json`. Repeatable checks: `scripts/audit_running_app.py`; full demo acceptance tests: `backend/tests/test_acceptance.py`.
